# thread0 0.1.279

- Changed native browser timer calls in the desktop execution reconnect controller to avoid an Illegal invocation that interrupted approved own-account connections.
- Explicitly re-shared session history uses current sharing and folder permissions, independently of an old executor grant. Old account execution authority is not inherited.
- New device registrations automatically replace the least recently used registration of the same kind when the account limit is reached. Reconnecting the same installation reuses its active registration and removes duplicate entries.
- Collaborators using their own AI accounts now wait for the execution connection to accept input before a new session or shared-session account switch is presented as ready. Interrupted switches retain the same session and request for recovery.
- Added transport recovery for disconnected own-account sessions without automatically resending messages or restarting explicitly stopped work.
- Improved account and connection diagnostics, translated recovery guidance, model selection controls, and PWA recovery after updates.
- Existing CLI conversations can be found and resumed from Sessions, keeping the first Home focused on its central composer. Failed scans offer retry instead of an empty-history message.
- Improved transcript positioning, collaborator layouts, and typing responsiveness while downloading files.

Update both participating desktop apps when using a collaborator's own AI account. Older desktops that cannot confirm input readiness show an update requirement.

The Claude and Codex provider packages remain unchanged in this release.

Validation includes automated behavioral tests and release checks. Real-device collaborator scenarios remain subject to user validation.
