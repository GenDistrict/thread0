# thread0 0.1.232

This release brings together the connection recovery, collaborator entry, onboarding and account-limit improvements developed since 0.1.229. It also makes the release validation tools portable across Windows and macOS. Real-device acceptance of the changed experiences remains pending; automated checks are not a substitute for user confirmation.

## Highlights

- **Collaborator entry for organization accounts.** The organization sign-in path now starts the collaborator connection host, alongside the existing personal-account path. Host lifetime follows account changes and sign-out, without starting a duplicate host inside the sign-in overlay.
- **Connection and offline recovery.** Desktop account connection screens keep a recoverable offline state instead of restarting on repeated authentication notifications. Remote handles stale connection attempts, switching away from an unavailable PC, bounded read retries and diagnostic export on the device that requested it.
- **An account-switch exit throughout Remote.** Pairing, PC selection, invitation entry and account-checking screens expose account recovery, including retry and cancellation when sign-out fails. Loading, errors and an authoritative empty PC list remain distinct.
- **A clearer first visit.** Home explains what thread0 can do and that personal Claude or ChatGPT/Codex access is needed before offering a chat composer. Suggested tasks appear outside the message field and only fill a draft. Invitation entry also explains the collaborator route, which does not require the visitor to claim they installed thread0 on their own PC.
- **Localized usage and durations.** Usage-window labels include compatibility with older desktops that return labels without window metadata. Account-limit text and elapsed turn durations follow the selected language. Remote's desktop-download button receives layout corrections.
- **User-controlled limit recovery.** Desktop Home and account settings offer account-bound recovery where supported. Claude opens the selected account's interactive CLI; thread0 does not type or execute `/limit-reset`. Codex shows available reset credits and requires explicit confirmation before redemption. An uncertain response retains its idempotency key for retry. Opening or cancelling an offer does not redeem a credit, and Remote cannot invoke desktop reset actions.
- **Installed GPT app recovery.** When a full app-directory request is denied, supported installed-app results can still be shown with the remaining directory error disclosed. This does not imply access to every app or remove an upstream permission restriction.

## Verification boundaries

Release checks cover simulated state transitions, packaged boot and layout, authorized ordinary provider turns, live authentication and collaborator service probes, signed artifacts and published endpoints. Actual reset-credit redemption is reserved for the user and is not performed by automated release checks. Physical Mac/phone connection acceptance and the live reset flow remain awaiting user validation.

The earlier 0.1.231 Mac candidate checks failed in test tooling before packaging: temporary-directory aliases and a Windows-only shell invocation. The next version preserves that history and uses native-host shell checks plus temporary-path boundary regressions; it does not rewrite the earlier tag or claim those failed jobs passed.
