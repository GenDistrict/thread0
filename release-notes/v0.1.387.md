# thread0 0.1.387

Windows ships as 0.1.387 and macOS (Apple Silicon) as 0.1.388 with the same changes (the macOS build was re-tagged after a test-only fix).

HTML results open as a live page you can comment on, Git worktrees from the project list, connectors that explain themselves, and stronger organization controls for credentials, connectors and plugins.

## Changes

### Results and web preview
- HTML results open as the real page, with the CSS, scripts and images from the same folder. **View** shows the running page; **Edit** takes comments on it the same way as the web preview.
- Comments in the web preview treat a route such as `#/settings` as its own page. A comment whose element is gone leaves the screen and stays in the list with its page address.
- On a display set to 150%, HTML and web-preview captures could be laid out one or two pixels off; they now match the requested size exactly.
- A result file mentioned in a chat by its relative path opens from the conversation, in the PC app and on the phone.
- Code blocks in the PC app show **Copy** and **Run** again (the code box was painting over them).

### Sessions and projects
- **Git worktrees**: from a project's row you can list, create and clean up worktrees. Each one appears as its own project, so sessions start and resume inside it.
- Until you send your first message, the home message box suggests a first task.
- When a conversation hits a usage limit, **Send** first offers to continue on another signed-in account of the same AI.
- The new-session folder prompt lists the folders you may use first.
- Security-check turns wait for the name-detection model to be ready instead of being refused.
- On Mac, project names, previews and titles no longer show the internal response-language block, and the conversation no longer jumps when a turn ends.
- Claude sign-in in the terminal: pressing Ctrl+C there is now explained (it stops the sign-in; copy by selecting with the mouse and right-clicking).

### Connectors
- The Connectors screen (PC app and phone) explains what connectors, plugins and GPT apps are and when they apply. You can fill in a connector by pasting the setup text from its documentation.
- After you add a connector, open sessions of that account offer **Start a new session with the same settings**, so the new connector is available.

### Organizations
- **Invitations by email**: an invited person clicks the link in the email, thread0 opens, and it asks once to join and connect this PC. A PC whose account already belongs to the organization is asked once to connect.
- **Work folders**: allowed folders are read per operating system (`~/folder` works on Windows and Mac). When you start without picking a folder, the new project goes into an allowed folder, created if needed.
- **Blocking credential reads** now covers every route: files inside the work folder, shell commands, all three AIs and every permission mode. Blocked attempts are recorded in the audit log.
- **Connector allowlist**: a local connector must match its whole launch command (program and arguments), so allowing one package no longer allows every `npx` package. Claude account connectors (claude.ai) follow the same allowlist.
- **Plugins** follow the organization's allowlist: outside it they cannot be installed, and plugins already turned on are switched off in sessions with a notice. This now also applies to GPT.
- **Prompt-injection check** also reviews connector results in GPT sessions (attachments are checked for every AI, web results in Claude sessions).
- **Usage limits** show what is left, and a notice appears from 80% and at the limit, on the PC and the phone.
- Organization announcements reach a phone that connects later.
- Strict audit keeps counting across an app restart; the activity-time notice is marked as seen only once it was actually shown.
- Routine-draft and app-connection cards in a shared session go only to the host, never to a guest.
