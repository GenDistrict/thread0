# thread0 0.1.310 (Windows) / 0.1.312 (macOS)

This release makes adding AI accounts a one-click step, connects local AI servers automatically, keeps collaboration sessions clear when the PC running them stops, and lets organizations see and enforce their security policy before it blocks anyone. It includes all changes since 0.1.299. The macOS build is numbered 0.1.312: it is the same release plus one fix so Local AI shows model file names from servers on other computers correctly.

## Changes

### Accounts and models
- Adding an AI account takes one click. Choose Claude, GPT or Local AI; the name, color and folder are set for you, and Claude or GPT sign-in starts right away. The "+ Add account" chip sits at the end of the account row on Home, and the Remote card's button now reads "+ Add device".
- Local AI connects by itself. thread0 finds every local AI server running on this PC (llama.cpp, LM Studio, Ollama, vLLM) and puts all of their models into one account, so a session can pick any of them. For llama.cpp, the server's real context size is used, so automatic compaction happens at the right point. If no server is running, thread0 uses model files on this PC; if there are none, it says so in place and lets you search again.
- Model pickers show only the newest generation of each Claude model, with correct names such as Sonnet 5.5. GPT-6.1 Sol is the default GPT model. Effort offers "Automatic" first on the PC and on Remote.
- Claude sign-in inside the app opens the sign-in page only when you ask for it and never ends early. GPT signs in through this PC's browser, and a new GPT account no longer fails right after starting.
- Deleting an account no longer leaves a "signed out" record behind.

### Collaboration
- When the collaborator whose account runs a shared session can no longer provide it, the session continues on the host's default account and the host is told exactly why: the invitation was revoked, the period ended, the collaborator left, the session was unshared, or the collaborator stopped using their account on their own PC. If no host account can take it, the session says it needs an account and offers to switch.
- A message sent while the PC running the AI has quietly disconnected (for example after sleep) now shows "connecting" within seconds and keeps your draft, instead of waiting 30 seconds and saying delivery could not be confirmed.
- Stopping a turn in a collaborator's session stops only that turn; the next message is answered. Sessions running on another person's GPT subscription no longer stay stuck on "Working…".
- Invitations can end on a date or never end, and the host can change a pending invitation's role, period and account rules before it is accepted.
- The first time each collaboration action happens, a short guide explains what happens, who can see what, whose subscription is used and how to undo it.
- Remote can add reference folders to a running session, and session renames appear on the PC and on Remote right away.

### Remote (phone and browser)
- Remote reconnects on its own after a network drop instead of waiting until you switch apps, and no longer mistakes its own reconnection for "another tab took the connection".
- Tapping the message box no longer jumps to the bottom while you read earlier messages, and the previous-message arrow loads earlier history when needed.
- Chat order stays correct after reloading or reconnecting, and loading screens match the screen that replaces them.

### Organizations
- Security checks and security mode required by the organization appear locked on in Settings on the PC and on Remote, and Settings warns three days before the policy must be refreshed.
- Organization policy now also applies to personal subscriptions on an enrolled PC, and removing a member from the console releases their PC.
- An enrolled PC signed in with a different thread0 account keeps enforcing the policy and says that policy updates and audit uploads resume when the enrolled account signs in, instead of showing that account as the owner.

### Updates and sessions
- Updates download only the parts that changed, show progress while downloading and installing, and need two clear steps: get the update, then install and restart. PCs on very old versions are brought forward by a small update helper.
- Routines can continue an existing session in their folder and run unattended in Auto, where risky actions are declined and counted instead of waiting forever.
- Auto runs routine work by itself and asks before deleting existing files outside the work folder or reading credential locations.
- GPT background terminals (dev servers, long builds) appear in the session's task list and can be stopped.
