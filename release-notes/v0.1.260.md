# thread0 0.1.260

This release fixes typing lag in long sessions on the desktop, stops an unexpected Windows administrator prompt, and lets collaborators work without a shared folder.

- Long sessions no longer slow the message bar. The transcript now skips layout and painting for rows that are off screen, and the composer no longer re-renders while a reply streams. In a 2,000-message session a keystroke went from about 220 ms to about 40 ms under 4× CPU throttling, and streaming replies keep flowing while you type.
- No more repeated "User Account Control" prompt for `codex-windows-sandbox-setup.exe`. Codex prefers an administrator-installed sandbox when nothing is configured and asked on every new process; thread0 now runs GPT sessions in the unelevated sandbox unless you set `windows.sandbox` yourself in Codex's config. The elevated setup remains an explicit action on the collaborators screen.
- thread0 now starts with the computer: the app registers itself as a login item (default on, with a toggle in Settings on both the PC and Remote), so your phone can reach the PC after a reboot without anyone opening it.
- Collaborators can start new sessions in their own folder even when the host has not shared one. Observers do not get a folder, and folder policies still apply.
- The same person can no longer be invited twice to the same PC while an invitation is pending or a connection is active; the form explains what to do instead.
- Already-accepted invitations no longer reappear as new ones on the phone; only undecided invitations are offered.
- Desktops that were signed in before diagnostics shipped now record consent on start, so their connection metrics and failure reports are uploaded like everyone else's.
- The collaborator direct-message bar on the phone sits on the screen bottom with the same spacing as session chat.
- Remote (early access): the two product-owner accounts can invite collaborators from the phone.

Update the host PC and refresh Remote to use the matching implementation. Automated fixtures and package checks do not replace real-device acceptance; user live validation remains pending.
